# A8E Compatibility Work Summary

This document records the emulator changes investigated through September 11,
2026, grouped by the software that motivated them. It complements
`implementation/NOTES.md`, which remains the chronological implementation log.

## Shared System Changes

### PAL and NTSC

The browser and native emulators now carry the selected video standard through
the boot path. PAL and NTSC use their own timing, line count, aspect handling,
palette data, and `$D014` identification value. PAL remains the default; NTSC
uses 262 lines and reports `$0F` at `$D014`, while PAL reports `$01`.

Affected files include:

- `jsA8E/index.html`
- `jsA8E/style.css`
- `jsA8E/js/app/ui.js`
- `jsA8E/js/core/{hw,atari,io,state,app_proxy}.js`
- `jsA8E/js/render/{palette,software}.js`
- `jsA8E/emulator_worker.js`
- `A8E/{A8E.c,AtariIo.c,AtariIo.h,Gtia.c}`

### Memory Expansion

The browser UI and native emulator support the 130XE 128K profile. PORTB bank
selection and the CPU/ANTIC extended-memory windows are represented separately.
The native command line exposes this profile with `-128K`, and startup logging
reports the selected memory configuration. Larger RAMBO and COMPY profiles were
investigated but are not considered fully compatible.

Affected files include:

- `jsA8E/js/core/{memory,io,state,atari,app_proxy}.js`
- `jsA8E/js/app/ui.js`
- `jsA8E/emulator_worker.js`
- `A8E/{A8E.c,AtariIo.c,AtariIo.h,Pia.c}`
- `A8E/README.md`

### POKEY, Audio, and Diagnostics

POKEY timer initialization was corrected when software configures an inactive
timer after STIMER. The native audio path gained negotiated-format handling for
Windows SDL devices, including WASAPI float stereo output, and diagnostic CSV
metrics. The browser API gained reusable CPU, memory, SIO, NMI, breakpoint,
trace, disassembly, and Chrome CDP inspection points.

These facilities are general-purpose and should remain. AtariWriter-specific
probes and placeholder devices were removed after that investigation was
paused.

Affected files include:

- `jsA8E/js/core/{pokey,pokey_sio,cpu,antic,state,atari,app_proxy}.js`
- `jsA8E/emulator_worker.js`
- `jsA8E/tests/cdp_diagnostic.js`
- `A8E/{A8E.c,Pokey.c,Pokey.h,AtariIo.c,AtariIo.h}`

## Karate Champion

### Problem

Karate Champion loaded its demo correctly but hung or crashed when START was
pressed. The display could continue showing animated rainbow text, indicating
that the machine was not completely stopped, while the main game path was not
progressing.

### Changes

The 6502 NMI dispatch logic was corrected so a new NMI edge can remain pending
while an earlier NMI handler is active. The old software `nmiActive` guard could
discard an NMI that real hardware would preserve at the CPU interrupt level.
A single pending flag is retained, so interrupts are not queued without bound.

POKEY timer setup was also corrected for software that configures a timer after
an earlier STIMER. The timer is armed without resetting an already-running
phase. This was important for software using timing-sensitive audio or input
processing during the transition into gameplay.

The native C core received the corresponding NMI behavior so the two emulator
implementations remain aligned.

### Result

The fix was verified with Karate Champion: the demo-to-game transition now
completes and the game starts in both jsA8E and native A8E.

### Affected Files

- `jsA8E/js/core/cpu.js`
- `jsA8E/js/core/{antic,atari,state,io,pokey}.js`
- `jsA8E/js/app/automation/utils.js`
- `jsA8E/emulator_worker.js`
- `jsA8E/tests/cpu_interrupt_step_regression.test.js`
- `A8E/6502.c`
- `A8E/Pokey.c`

## Animal Party

### Problem

Animal Party reached its bitmap presentation with music. After the joystick
button was pressed, the expected green memory-display glitch occurred, but
jsA8E remained at that transition instead of completing the second disk load.
SIO Turbo was disabled during testing, so the issue was not caused by the user
load-speed option.

### Changes

The disk READ response was split into the two SIO phases documented by AHRM:

1. command acknowledgment (`A`), followed later by
2. complete/data response (`C`, payload, checksum).

The pending read phase is preserved in emulator state and snapshots. This
prevents the next command or data byte from being interpreted at the wrong SIO
phase during the loader's button-triggered second load.

The investigation also added temporary captures for the loader DCB, `$A527`,
`$A52B`, POKEY serial registers, vectors, disassembly, and post-button SIO
events. Those captures established that the loader returned to its boot-load
path after the button and helped validate the phased response change.

### Result

Animal Party became a successful compatibility test: it loads through the
presentation, accepts the button transition, completes the second load, and
starts the game.

### Affected Files

- `jsA8E/js/core/{state,memory,io,pokey_sio}.js`
- `jsA8E/js/core/app_proxy.js`
- `jsA8E/emulator_worker.js`
- `jsA8E/tests/cdp_diagnostic.js`

## AtariWriter Plus XE

### Problem

`ATR/AtariWriterPlusXE.atr` loads its initial disk content and reaches the
AtariWriter startup path, but jsA8E eventually returns to the XL/XE cold-start
path. The same image loads in Altirra and on real Atari hardware without an 850
or printer connected.

### Tests Performed

- Tested with 130XE 128K and with 64K configurations.
- Disabled SIO Turbo to exclude accelerated transfer timing.
- Compared sector-read sequences with Altirra.
- Observed repeated Type 1 SIO polls to device `$50`, command `$3F`, AUX1
  `$00`.
- Added direct Chrome CDP automation to mount the ATR, reset, run, pause, read
  memory, inspect CPU state, and collect SIO events without manual copy/paste.
- Added CPU trace capture around reset vector `$C2AA` and cold-start entry
  `$C2D0`.
- Added diagnostics for writes to `DSTAT` (`$0303`), `TIMFLG` (`$0317`), and
  the XL/XE checksum window `$BFF0-$BFFF`.
- Compared Altirra breakpoints and memory traces, including the cleanup path at
  `$C343`.

### Findings

The reset is not caused by `CPU.reset()` being called by the emulator. The
guest OS enters its cold-start path through the reset vector after a checksum
failure. The observed sequence is consistent with software deciding that the
warm-start state is invalid, rather than with a host-side exception or an
emulator API reset.

Altirra's trace shows the absent-device flow eventually reaching normal SIO
cleanup: `DSTAT` changes to `$01`, the OS reaches `$C343`, then `TIMFLG` and
`DSTAT` are cleared. jsA8e instead remains in or returns to repeated `$50/$3F`
polling, with SIO state and timeout completion differing from that sequence.

The checksum diagnostics showed the OS comparison at `$C4D3` calculating
`$9B` while the expected RAM checksum value at `$03EB` was `$00`. This is a
consequence of the cold-start decision; it does not by itself prove that the
ROM is corrupt. The reset stack and trace point back to the OS path after the
SIO wait rather than to a hardware reset source.

### 850 Device Investigation

An encapsulated dummy 850 device was evaluated, but it was not valid without
real 850 firmware and was removed rather than leaving a misleading fallback.

Registering that dummy by default was tested and was incorrect for this use
case. It makes AtariWriter follow the 850 bootstrap path even though the
reference machines have no 850. The fake booter then leads to invalid code and
another reset. The current code therefore keeps `$50` electrically absent by
default.

### Technical Diagnosis

The remaining bug is most likely in the generic emulation of an unanswered SIO
Type 1/2 poll: the bus must remain silent, but the OS must still observe the
same timing and completion state as real hardware. The unresolved difference
is the interaction among SIO command retries, POKEY serial status/IRQ state,
`TIMFLG`, `DSTAT`, and the OS VBI timeout. Returning a fabricated ACK, NACK,
850 DCB, or placeholder boot code is not a valid workaround and is intentionally
not the current default behavior.

This diagnosis is still pending final verification against a complete Altirra
and jsA8E trace captured from the same starting point.
