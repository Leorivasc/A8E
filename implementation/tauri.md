# Tauri Desktop Shell

The `src-tauri/` project wraps the existing `jsA8E` static frontend in a
native Tauri window. The emulator core remains JavaScript; no emulation logic
is duplicated in Rust.

## Browser Development

The normal browser workflow remains unchanged:

```sh
python -m http.server 8000
# open http://localhost:8000/jsA8E/
```

## Tauri Development

Tauri development uses the same static server URL. Bind the server to the
loopback interface from the repository root in one terminal:

```sh
python -m http.server 8090 --bind 127.0.0.1
```

Then start the native shell from another terminal after installing Rust and
the Tauri CLI:

```sh
cargo tauri dev --config src-tauri/tauri.conf.json
```

The native WebView has no browser tab bar, so browser chrome accelerators such
as `Ctrl+T` are not competing with AtariWriter. The existing canvas keyboard
handler can therefore receive them as normal application input.

The `devUrl` currently points to `http://127.0.0.1:8090/jsA8E/`. Because the
repository does not define a Tauri `beforeDevCommand`, the Python server must
be started manually. Port `8090` only matters during development; if another
local service already uses it, choose another free port and update both
`src-tauri/tauri.conf.json` and the server command.

The desktop shell intentionally uses the main-thread emulator backend. Some
WebKitGTK versions expose `OffscreenCanvas` to workers but do not provide a
usable 2D context there; the app detects Tauri and avoids that worker path.

Tauri's native drag-drop handler remains enabled in the desktop window. The
frontend listens to Tauri's file-drop event, reads the dropped paths through a
small Rust command, and forwards `File` objects to the existing Disk Library,
HostFS, and screen drop handlers. Browser usage continues to use the existing
HTML5 `dataTransfer` path.

## Bundling

Release builds use `frontendDist: "../jsA8E"` and package the static frontend
inside the application:

```sh
cargo tauri build --config src-tauri/tauri.conf.json
```

Packaged applications do not use `devUrl`, Python, or a local HTTP server.
The frontend is embedded in the application and served by Tauri's internal
asset protocol, so the AppImage does not bind TCP port `8090` or any other
local listening port and cannot conflict with another service for that port.

The repository also includes a Linux build helper. Run it from any directory
inside the repository:

```sh
./scripts/build-tauri-linux.sh
```

The script loads the rustup environment when available, checks Cargo, the
Tauri CLI, and the required Linux development packages, then prints the
generated `.deb` and `.rpm` artifacts. It defaults to these native Linux
packages because AppImage's external `linuxdeploy` toolchain can require
additional downloads. To request AppImage as well:

```sh
A8E_TAURI_BUNDLES=deb,rpm,appimage ./scripts/build-tauri-linux.sh
```

The current configuration intentionally does not add a global-shortcut
plugin. AtariWriter shortcuts should be active while the emulator window has
focus, not globally across the operating system.

## Prerequisites

- Rust toolchain with Cargo
- Tauri CLI v2
- Platform WebView development dependencies required by Tauri

The Tauri wrapper has not yet been compiled in this checkout because Rust and
Cargo are not currently installed in the development environment.

## Portability

Rust, Cargo, the Tauri CLI, Python, and the Linux GTK/WebKitGTK development
packages are build-time requirements. They are not required by users running a
packaged application.

- Windows uses Microsoft WebView2. Current Windows installations commonly
  provide it or can install it separately.
- macOS uses the system WebKit framework.
- Linux uses WebKitGTK from the distribution. Debian packages generated by
  Tauri declare runtime dependencies such as `libwebkit2gtk-4.1-0` and
  `libgtk-3-0`, so Linux packaging must target a known distribution baseline.

The browser workflow remains portable and does not depend on Tauri. Python's
HTTP server is only a development convenience and is not included in the
desktop application. ROM images and disk files remain user-provided files.

For a fully offline release, the remaining Font Awesome and `fflate` CDN
references in `jsA8E/index.html` should be replaced with local assets before
publishing installers.
